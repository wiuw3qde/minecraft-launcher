# MC 启动器 v0.2.3

本版正式上线「存档时光机」主线的第一、二阶段。思路很简单：启动器早就握着 `level.dat`、`latest.log` 和自动备份这些数据，但过去只拿它们排错；这一版开始，让它们反过来服务玩家。

> 全部数据**纯本地处理，不上传、不上云**。所有新功能默认只读，只有你明确点选才会写文件。

## 🗂 世界存档卡片

在「版本管理 → 世界」里，每个存档下方会展开一张卡片：

- 世界名、**种子**（一键复制）、游戏时长（含约第 N 天）、最后游玩时间
- 坐标、维度、出生点、游戏模式与难度、玩家状态
- 建档版本 / DataVersion、作弊开关、是否有图标

顺手修掉两个**长期存在的数据错误**（不修的话卡片显示的就是错的）：

| 问题 | 说明 |
| --- | --- |
| 世界名/最后游玩/模式一直读不出来 | 真实 `level.dat` 是 `{Data:{...}}` 嵌套结构，旧代码按顶层取 `LevelName`/`LastPlayed`。旧测试用扁平假数据才"通过"。现已统一走 NBT 摘要，并兼容扁平旧档。 |
| 大种子显示错 | MC 种子是 64 位整数，`Number()` 会丢精度（`-4172144997902289642` 曾显示成 `…600`）。现按精确十进制文本解析与展示。 |

## 🛡 跨版本开档守卫

降级或不换档开旧存档是丢档的头号原因，主流启动器基本不管。这一版在**启动前**做只读评估：

- 比对存档与「上次成功打开的版本 / DataVersion」，用**本地相对判据**，不硬编码会写错的 MC↔DataVersion 全表。
- 检出高风险时弹原生对话框三选一：**先做快照再启动** / **复制「升级前副本」再启动** / **取消启动**，可勾「以后不再提醒」。
- 只有你明确选择才新建文件，**绝不改动原世界**；任何异常或快照失败只降级提示，**绝不阻塞启动**。
- 开关在「设置 → 存档安全」，默认开启；关闭后仍会记录状态，方便日后重开。

**已知限制（如实说明）**：启动器无法知道你进游戏后实际打开的是哪个世界，因此会把 `saves/` 下所有世界记为本轮启动版本，换版本时可能对没打开的世界也提醒（偏保守）。可用开关或「以后不再提醒」缓解，后续版本会结合冒险日记的进世界事件精确化。

## 📖 冒险日记

「版本管理 → 冒险日记」把 `latest.log` 变成可回顾的时间线：

- 只从日志**尾部读 2MB**，按「进入世界 → 退出 / 崩溃」切成一局一局。
- 统计卡：游玩时长、进出次数、死亡、进度、崩溃 / OOM、联机、维度切换等；最近一局事件流按类型着色，支持一键复制摘要。
- 隐私边界：**只返回结构化事件**，不返回日志原文与未识别行，聊天内容一律脱敏。

## 🔧 其它修复

- 反馈页「打开 issue 链接」一直静默失败：preload 用 `app:openExternal`，主进程注册的是 `app:open-external`，通道名不一致，已统一。
- 复制存档副本使用的 `fs.cpSync` 在本机 Windows/Node 上会**直接段错误导致进程崩溃**（exit 139），已改为手写递归复制：不跟随符号链接、限制 5 万文件 / 4GB、失败自动清理半成品。
- **测试链假通过**：`optifine` 测试缺前置文件时 `exit 1` 掐断 `&&` 链，导致其后 10 组测试静默不执行，历史汇报曾据此误判「全套通过」。现改为优雅跳过，并用真实退出码校验。

## 🧪 验证

- `npm test` **真实退出码 0**（未用管道掩盖），新增 `worldinfo` / `worldguard` / `timeline` 等单测并加入测试链。
- `node --check` 全部通过；preload 的 99 个 IPC 通道与主进程 99 个 handler **逐一对应、无缺失**。

## ⚠️ 注意

- 冒险日记依赖 `latest.log`；若游戏内关闭日志输出或用清理工具删过日志，可能没有事件，属正常降级。
- 存档卡片、守卫、日记均为只读或显式确认后才写入，不影响现有存档与备份。
